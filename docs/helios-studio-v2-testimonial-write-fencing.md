# Packet 72: Testimonial create/update commit authority

Five actual-handler tests fail on integrated Packet 71: create and update accept actor revocation or invalidated asset authority after early image verification, and update accepts an image reference that changed during verification. The smallest correction retains provider inspection before the transaction and revalidates database authority at commit.

Create/update now require current locked editor authority. Content scope is recalculated on the transaction connection; update locks and re-reads its selected testimonial. A changed image reference returns 409, requiring a fresh submission against the current image rather than reusing an earlier unchanged-image exemption. The shared image validator locks the exact registered provider identity and rechecks owner/status inside the transaction. An absent legacy identity is protected with table share locks and rechecked; absence is determined from the locking query itself so an insertion between statements cannot bypass protection. No provider request occurs while these locks are held. Existing image retention, response fields, optional publish/featured fields, null-image clearing and exact unchanged legacy references remain supported.

Twenty-four observed HTTP/PostgreSQL races cover both tenants and methods: revoked membership, viewer role, stale session version, quarantined/transferred asset; update additionally covers record transfer and changed image references. Foreign images/records must be denied, injected failures must roll back all content and registry changes, and successful owned creation/replacement must retain unrelated content and registrations. Exact legacy references and clearing remain executable compatibility cases.

The content-image provider import is explicitly replaced only in the disposable rehearsal with a strict synthetic HeadObject adapter; unexpected commands/keys fail. It has no network fallback. This establishes database and request authority, not hosted object existence/CDN delivery. Schema/index/access postflight, exact-head regression/TypeScript/Chromium, independent artifact hash/parse and merge-tree equality remain required gates. No schema migration, provider deletion, credentials or production operations. Phase 1 remains open; production ON HOLD.
