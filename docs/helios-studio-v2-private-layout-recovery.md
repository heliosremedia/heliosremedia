## Bounded contract and evidence

The request still contains the complete {order,collapsed} pair. Headers x-layout-revision, x-layout-request and x-layout-workspace are now required. The workspace header is only a precondition against the authenticated stored context, never an authorization source. Headerless older clients receive 409/reload instead of bypassing stale-tab protection. New writes reject incomplete, duplicate or unknown section ids; historical read normalization and all five defaults remain unchanged.

One transaction locks Workspace, AdminUser, then membership in the established account-write order. It rechecks active user, session version and active membership (when tenant mode is on), including VIEWER compatibility. It compares the opaque SHA-256 revision of user/workspace/stored preferences before writing, checks exactly one affected row, then reads back and validates committed preferences and generation. The JSON layoutGeneration changes on every admitted write, including identical choices, so returning to a previous order does not revive an old revision. No schema/migration is needed. A failed count or readback throws and rolls back. No SiteSettings record is a parent of this private value; unrelated singleton changes cannot redirect it.

Acknowledgement protocol 1 binds scope private-homepage-layout, intent replace, request id, user id, workspace, previous revision, new revision and exact authoritative preferences. Browser freezes the input, synchronously admits one operation, disables layout mutation controls during saving/held recovery, and never overwrites sibling content. It rejects malformed/foreign/unmatched receipts, bounds fetch and JSON to 20 seconds, fences late/remounted/obsolete-context callbacks, and holds the attempted layout after conflict or uncertainty. Recovery uses the existing ephemeral shared homepage draft-copy registry, with explicit retained-copy confirmation before document reload and no automatic replay or persistent draft storage. Older responses cannot follow a newer save: pending writes block admission; timeout holds writes; remount/context changes invalidate callbacks. Initial URL-hash expansion now reveals the panel locally without issuing a write, preventing recovery reload from automatically saving.

Actual organizer tests cover duplicate admission, retained unknown result, identity/workspace/revision/request/scope/intent/order rejection, 409, frozen request, blocked in-flight edits, old-handler rejection, revision advancement, fetch/JSON timeouts, unmount/context switch, and retained-copy reload without replay. Actual route code runs through narrow SQL delegates on PGlite, covering stale writes, authoritative readback/generation advancement, completed transfer/null owner, revocation, inactive/session-invalid users, zero counts, readback rollback, malformed section sets and foreign submitted context. Existing default/legacy normalization tests remain intact. This is isolated SQL evidence, not generated-Prisma or independent-connection Neon concurrency.

Already-safe boundaries preserved: #313 zero-row update rejection; current user/workspace predicates; required AdminUser owner in production schema; private/public layout separation; deterministic legacy normalization. No network automatic retry existed; the new hold additionally prevents manual blind repeats. No partial child-row reorder exists: the complete preference JSON is one atomic row update.
